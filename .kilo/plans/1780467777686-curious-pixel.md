# Plan: Fix Missing Kos Images on Landing Page

## Problem Analysis

On the landing page (`/`), kos card images use `data-src` for lazy-loading via `initLazyLoad()`. Some kos images are missing.

Two overlapping root causes were identified:

1. **Missing fallback placeholder:** The blade template (`landingPage.blade.php`) falls back to `asset('images/kos-placeholder.png')` when no primary photo exists, but **this image does not exist** in `public/images/`.
2. **Empty `photos` relation for some kos:** `KosService::getFeaturedKos()` (and `getRecentKos()` / `getNearbyKos()`) eagerly loads photos with the `primaryLowering()' scope, which requires `is_primary = true`. Some kos have photos in the DB but none are marked as `is_primary = true` (because `KosService::uploadPhotos()` does not set this flag, or existing data is old). As a result, `$kos->photos` is empty, so the fallback placeholder is used, but it's missing — leading to broken images.

The `php artisan storage:link` error is a red herring; `public/storage` already exists as a valid junction to `storage/app/public` and files are accessible.

## Implementation Plan

### 1. Fix `KosService` Eager Loading (Primary Fix)
Update photo eager-loading in `getFeaturedKos`, `getRecentKos`, and `getNearbyKos` so that photos are always returned if they exist, but primary photos are prioritized.
- **File(s):** `app/Services/KosService.php`
- **Change:** Replace `->primary()` with `->orderBy('is_primary', 'desc')->orderBy('order', 'asc')` in the `with()` calls.
- **Impact:** `$kos->photos->first()` in `landingPage.blade.php` will always get the best available photo (primary first, otherwise first uploaded).

### 2. Fix Missing Placeholder Image
Ensure the fallback placeholder used in views actually exists.
- **File(s):** `landingPage.blade.php` (and any other view referencing it)
- **Action:** Change references from `images/kos-placeholder.png` to an existing image in `public/images/` (e.g., `images/kos-bedroom.png` or `images/kos-1.png`), OR copy an existing suitable image to `public/images/kos-placeholder.png`.

### 3. Fix `KosService::uploadPhotos()`
Ensure newly uploaded photos set `is_primary = true` for the first/only photo, matching the behavior in `DashboardController::store()`.
- **File(s):** `app/Services/KosService.php`
- **Change:** When creating the first photo for a kos, set `is_primary => true`.

### 4. Fix Existing Data
Run a one-time script to set `is_primary = true` for the first photo of any kos that currently has no primary photo.
- **Action:** Run a PHP one-liner or Tinker script to update the database.

### 5. Address `public/storage` Link Error
Reassure the user and optionally recreate the symlink for a clean state.
- **Action:** Remove the existing `public/storage` junction and recreate it cleanly with `php artisan storage:link`.
